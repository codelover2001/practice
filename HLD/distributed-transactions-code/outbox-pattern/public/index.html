Outbox Pattern

The problem (Dual Write): Writing to DB and Kafka separately — if one fails, data is inconsistent. No way to make both atomic.

The solution (Outbox): Write order + event to the SAME database in ONE transaction. A separate publisher reads the outbox table and publishes to Kafka. If publisher crashes, it picks up where it left off. No events lost.

1. Dual Write (BROKEN — see the inconsistency)

2. Outbox Pattern (CORRECT)

Try: create 3 orders via outbox, then start publisher — all 3 get published. Or: start publisher, stop it, create orders, restart — picks up where it left off.
